# Reference register

## Purpose

This register records influence boundaries and asset provenance requirements. It prevents accidental copying and makes new reference use deliberate.

## Approved directional references

- Apple product pages and iOS: calm hierarchy, material quality, typography, and spatial confidence.
- Figma Community: design-workspace vocabulary such as selection boxes, labels, prototype connectors, and component artifacts.
- Linear, Arc, and Framer: precise interaction feedback, refined surfaces, and restrained motion.
- Pinterest editorial posters and modern Swiss layouts: asymmetric editorial rhythm, scale contrast, and intentional negative space.
- Supplied Helena mockups: soft white canvas, pink/periwinkle atmosphere, modular cards, portrait treatment, and evidence hierarchy.

These are principles only. Do not copy an arrangement, branded asset, interaction, illustration, text, or code implementation from any reference.

## Asset provenance rules

Every image, logo, icon, font, illustration, and QR destination must have an owner, licence/permission status, and intended use. Store original source details outside public code if sensitive. Use official brand assets only under their usage rules. Do not generate or publish a portrait likeness without Helena’s approval.

## Adding a reference

Record: source, date accessed, what principle is useful, what must not be copied, and whether it creates an asset/licence dependency. If a reference cannot be explained as a principle, it is not an approved implementation reference.
