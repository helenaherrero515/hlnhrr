# Style guide

## Purpose

This guide preserves Helena’s written voice and brand expression. It governs words, labels, and consistency; it does not invent professional claims. Use it with `CONTENT.md` for structured content and `DESIGN_SYSTEM.md` for typographic mechanics.

## Voice and tone

Write with calm confidence, warmth, and specificity. Helena speaks as a thoughtful practitioner: direct about what she made, honest about collaboration, and curious about improving systems. Prefer active, concrete verbs: designed, mapped, prototyped, built, tested, clarified, collaborated, shipped. Avoid hype, inflated superlatives, and empty “passionate” language.

## Hierarchy and capitalization

Use sentence case for headings, navigation, buttons, card labels, and badges unless a proper name requires title case. Preserve official capitalization for companies, awards, tools, and credentials. Use short noun phrases for labels (`Selected work`, `Product design`) and complete sentences for explanatory copy.

## Microcopy

Buttons begin with an action: `View selected work`, `Read the case study`, `Download résumé`, `Start a conversation`. Avoid `Click here`, `Learn more`, and vague `Explore`. Use `View all projects` only when a visible project collection establishes what “all” means.

Availability should be factual and time-safe: `Open to UI/UX internship opportunities` only if currently verified. Dates use `Jan 2026 – Jun 2026` for ranges and `Feb 2026` for a single credential month. Use `50+` only for a verified lower-bound metric. Skill names follow official product names: `React`, `JavaScript`, `Figma`, `Google Analytics`.

## Tags, badges, icons, and emoji

Tags identify discipline, tool, or method; limit each card to 3–5. Badges communicate a verified status, award, or placement, not generic praise. Use Lucide icons for interface actions. Emoji are not UI icons; use them only in approved editorial copy or data when they have semantic meaning and are not the sole carrier of information.

## Consistency rules

Use first person for Helena’s point of view (`I design…`) and third person only in metadata or externally authored testimonial context. Use ampersands sparingly in branded labels, not in body copy. Do not alternate between “UI/UX”, “UX/UI”, and “product design” without intent; choose the term matching the actual role.

## Future scalability

New page copy starts with visitor intent, one primary heading, concise lead, and evidence-based supporting details. Case studies follow the same factual, outcome-oriented voice and identify Helena’s contribution separately from team output.
