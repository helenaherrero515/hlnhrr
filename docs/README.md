# Documentation index

## Purpose

`docs/` is the implementation handbook for Helena’s portfolio. The Product Vision and `IMPLEMENTATION_PLAN.md` define intent and delivery order; the documents below turn that intent into specific build rules. This file is an index, not a duplicate north-star document.

## Reading order

1. Read `IMPLEMENTATION_PLAN.md` for scope, gates, invariants, and the visitor loop.
2. Read `README.md` at repository root for product purpose and development workflow.
3. Read `DESIGN_SYSTEM.md`, `VISUAL_LANGUAGE.md`, and `LAYOUT_RULES.md` before creating visuals.
4. Read `COMPONENTS.md` and `TECH_STACK.md` before coding.
5. Read `CONTENT.md`, `PROJECTS.md`, and `STYLE_GUIDE.md` before writing copy or publishing project facts.
6. Read `ANIMATIONS.md` and `DO_NOT_DO.md` before adding interaction polish.

## Authority and conflict resolution

When documents disagree, apply this order: verified facts and accessibility requirements; Product Vision; Implementation Plan; concern-specific handbook; existing stable contracts. Do not resolve ambiguity by inventing public claims, repeating styling, or adding features outside MVP scope. Record a deliberate new decision in the concern document it affects.

## Reference mockups

The supplied reference images establish the desired density, soft white ground, modular card rhythm, product-workspace motifs, and pink/periwinkle accent behavior. They are direction, not a screen to reproduce. Preserve the visual principles while composing an original experience from Helena’s verified content.
